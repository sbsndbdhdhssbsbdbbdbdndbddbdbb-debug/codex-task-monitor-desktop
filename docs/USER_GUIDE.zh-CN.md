# Codex Task Monitor 使用手册

[项目首页](../README.md) | [English](USER_GUIDE.en.md) | [自制桌宠](CUSTOM_PETS.md)

这是独立的 Windows x64 状态监视器，不是 Codex 任务执行器。先在 Codex 中发起工作，再用这里的列表和提醒跟踪；回复、授权、继续、停止和成果验收都回到 Codex 操作。当前界面主要为中文。

本手册适用于 **`v0.1.0-beta.1`（预览版，非稳定版）**。版本说明及可用附件见 [Release 列表](https://github.com/sbsndbdhdhssbsbdbbdbdndbddbdbb-debug/codex-task-monitor-desktop/releases)，维护范围见[安全说明](../SECURITY.md)。

## 快速工作流

| 想做什么 | 操作 | 结果与检查 |
| --- | --- | --- |
| 开始监控 | 解压后运行 `CodexTaskMonitor.exe`，在 Codex 中正常发起任务 | 等待首次扫描；没有任务时先检查分组、筛选和暂停状态 |
| 扫一眼多个聊天 | 点击桌宠展开列表，切换“进行中 / 需处理 / 最近完成” | 展示从本机记录推断的状态，不是完成百分比 |
| 回到聊天 | 悬浮列表点任务；主窗口双击任务或点打开按钮 | 尝试打开对应聊天；定位失败时在 Codex 中手动查找 |
| 看详细信息 | 主窗口单击任务 | 右侧显示活动、已用时、时间、目录和识别到的子任务 |
| 安静工作 | 开启“勿扰” | 继续监听，抑制提醒；不要把“暂停监听”当成暂停 Codex |
| 找回桌宠 | 托盘打开任务中心，点“显示桌宠” | 从隐藏或小圆球状态召回；也可用托盘“显示 / 隐藏桌面状态” |
| 换伙伴 | “桌宠库”内选择已有角色，或在“发现桌宠”下载 | 下载成功后立即应用，库窗口保持打开 |

## 下载、解压与首次运行

1. 访问 [Release 列表](https://github.com/sbsndbdhdhssbsbdbbdbdndbddbdbb-debug/codex-task-monitor-desktop/releases)，查看 `v0.1.0-beta.1` 的说明和可用附件，选择 `CodexTaskMonitor-win-x64.zip`，不要改用不明镜像。
2. 将整个 ZIP 解压到自己的可写目录，例如 `<app-folder>`。这不是安装向导，不需要在压缩包中双击运行。
3. 启动 `CodexTaskMonitor.exe`。该自包含发布包已包含 .NET 8 运行时，无需另装 .NET Desktop Runtime。
4. 保持 Codex 正常使用。监视器默认从当前 Windows 用户的 `%USERPROFILE%\.codex` 查找记录；目前没有用于切换任意 Codex 数据根目录的界面。

请保留包内的两份 README、`docs` 中英手册与自制桌宠说明、`LICENSE`、第三方和安全说明，以及 `licenses` 下的依赖/运行时许可材料。普通用户解压运行 EXE 无需 SDK 或 PowerShell 7；从源码发布才需要 Windows、受支持的最新 .NET 8 SDK 和 PowerShell 7。本预览版的构建基线为 SDK `8.0.427` / 运行时 `8.0.33`，步骤见[项目首页](../README.md)。发布默认目录为 `artifacts/publish/win-x64`，必须为空；重建时可用 `-OutputDirectory` 指定另一空目录。

.NET 8 的[官方支持截止日期为 2026-11-10](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)，内置运行时不会延长该周期。之后继续安全维护需要迁移框架，详见[安全说明](../SECURITY.md)，不应把本预览包视为长期受支持版本。

应用未签名，Windows 可能显示安全警告。确认下载来源、发布说明和组织安全要求；无法确认可信时停止运行。不要为了运行它关闭防护或绕过安全策略。

关闭主窗口会隐藏到托盘，**不是退出**。从通知区域的 Codex Task Monitor 图标右键选择“退出”才会结束程序。若提示已经运行，请找托盘中现有实例；再次启动不保证召回窗口。

## 状态怎么看

| 界面分组 | 当前判断来源 | 不应据此推断 |
| --- | --- | --- |
| 进行中 / In progress | 任务开始、思考、工具调用、输出等会话事件 | 还剩多少时间、完成了多少百分比 |
| 需处理 / Needs attention | 等待用户输入或识别到失败 | 已捕获每一种审批、权限问题或错误 |
| 最近完成 / Recently completed | 最近 24 小时内的完成记录 | 成果已测试、已提交或已被用户验收 |

这三个分组主要统计主任务；能关联到父任务的子任务放在详情中。不是每个内部状态都会显示：空闲、中止，以及默认超过 10 分钟没有新活动的 `Stale` 等状态不属于这三个显示分组。没有列出不等于任务已完成，长工具调用也可能被判为无新活动。

当前发现逻辑有最近记录数量上限，并依赖 Codex 本地数据库结构和 JSONL 格式。因此不能保证完整历史、每个聊天、每种等待输入情形或后续 Codex 版本都能识别。请以 Codex 中的实际状态为准。

悬浮“最近完成”列表中点击一项，会先确认这次完成记录并从悬浮列表移除，**即使随后跳转没有成功**；主窗口的“最近完成”仍可查看它。不会删除 Codex 聊天。

## 主窗口

- **查找：**搜索匹配任务标题、项目或当前活动；项目下拉框进一步筛选。清空筛选按钮恢复搜索和项目范围，不会删除数据。
- **排序：**“最近活动”按新到旧，“运行时长”按已用时长排序。时间来自记录，不是对剩余工作的预测。
- **详情：**单击任务查看监视器记录的标题、状态、项目、活动、已用时、最后活动、开始时间、工作目录及子任务。标题可能已被截短，不一定是原始消息全文。
- **打开：**双击列表项、选中后按 Enter、点箭头或“在 Codex 中打开”；子任务按钮也会尝试打开其聊天。Esc 或详情关闭按钮取消选择。
- **最近完成快捷项：**右侧未选中任务时的“刚刚完成的事”最多显示 3 项，点击会定位主窗口的最近完成记录。
- **检查监听：**刷新按钮手动读取一次；“监控状态”显示跟踪数量和上次检查情况，不是对任务成果的验证。

跳转通过 `codex://threads/<thread-id>` 和本机应用处理完成。Codex 安装、协议注册或版本变化可能导致只唤起应用、打开错误位置或无法跳转。监视器不能保证深链成功，也不会替你输入任务。

## 桌宠、小圆球与托盘

| 操作 | 当前行为 |
| --- | --- |
| 单击桌宠主体 | 展开或收起任务列表；列表里可切换三个分组、滚动、点任务 |
| 点“收纳为小圆球” | 变为约 48 x 48 的小圆球；点击圆球恢复桌宠，再点桌宠展开列表 |
| 按住桌宠或圆球拖动 | 可跨显示器移动；松开后按所在屏幕工作区约束位置，圆球会吸附到最近边缘 |
| 主窗口点“显示桌宠” | 显示桌宠并恢复非圆球状态，不必重新启动程序 |
| 托盘左键 / 右键 | 左键打开任务中心；右键可打开任务中心、暂停/恢复、切换勿扰、显示/隐藏桌面状态、退出 |

圆球数字优先显示需处理数量，否则显示进行中数量，**不是全部聊天数或进度百分比**。“设置”可控制悬浮窗显示、始终置顶和桌宠动画；系统关闭窗口动画时，应用动画也可能停用。

如果切换显示器或缩放后看不到桌宠，先用托盘打开任务中心并点“显示桌宠”，必要时退出后重新启动。多显示器拖动已在代码中实现，但不承诺每种 DPI、任务栏和显示器组合都能完全一致。

## 提醒、勿扰与暂停

在“设置”的“普通完成提醒”中选择：

| 选项 | 普通完成提醒 |
| --- | --- |
| 始终提醒 | 检测到符合条件的完成事件时提醒 |
| 仅在窗口后台时提醒 | 默认项；以监视器主窗口是否处于活动状态为判断，不是检测 Codex 是否在前台 |
| 只提醒需处理和失败 | 不发送普通完成提醒 |
| 关闭普通完成提醒 | 关闭普通完成提醒，不等于关闭所有异常提醒 |

等待输入、失败和中止事件有独立提醒逻辑；子任务完成和无新活动状态不弹普通完成提醒。短时间的更新可能合并成一个应用弹窗：单条弹窗尝试打开该聊天，多条合并弹窗打开任务中心。启动时读取旧记录不保证重放完成提醒。

“播放提醒声音”控制声音。“需处理提醒间隔”可设为 5 至 240 分钟，默认 30 分钟，用于仍待输入的任务，不是所有失败事件的定时重试。

| 控制 | 对监听的影响 | 对 Codex 任务的影响 |
| --- | --- | --- |
| 勿扰 | 继续监听，用于抑制弹窗和声音；主窗口、悬浮列表和托盘可切换 | 无，不回复也不继续任务 |
| 暂停监听 | 暂停后台自动读取，保留上次状态；手动刷新仍可读取 | 无，Codex 可能继续运行 |
| 退出监视器 | 停止本工具的监听和界面 | 不等于停止 Codex |

暂停不是静音开关，需要安静时使用勿扰。暂停时列表不是最新状态，已用时显示也不能证明任务仍在工作。

“登录 Windows 后自动启动”会登记当前用户启动项；“启动后直接进入托盘”控制主窗口是否显示。搬动或删除程序前，先在设置中关闭自动启动并保存。

## Petdex 桌宠库

1. 在任务中心点“桌宠库”。“我的桌宠”包含内置角色和当前可读取的本地包，点卡片立即切换，已有角色无需重复下载。
2. 切到“发现桌宠”后加载 [Petdex](https://petdex.dev/) 目录；可按角色、描述、类型或作者搜索，使用上一页/下一页浏览，每页 12 项。预览为缩略图，不是所有动作的完整兼容性验证。
3. 点“下载并使用”，成功后应用到桌面并回到“我的桌宠”；也可在“添加新伙伴”中粘贴目录中真实角色的 slug、`https://petdex.dev/pets/<slug>` 或 `npx petdex install <slug>`。
4. 粘贴的命令文本只用于解析 slug，**不会执行命令**，无需 Node.js、npx 或 Petdex Desktop。任意下载链接、本地路径和 ZIP 不是该输入框支持的导入格式。
5. 加载时可取消，失败可重试或使用内置/已下载角色；缩略图失败可点预览重试。“官方浏览”在默认浏览器打开 Petdex，不会代替应用内下载。
6. 在“我的桌宠”点删除图标并确认，会删除该角色整个本地包；删除正在使用的下载角色时先切回内置角色。内置角色没有该删除入口。“刷新”在本地页重扫包，在发现页重载在线目录。

目前没有任意本地文件夹、ZIP 或单张图片的一键导入。自制素材需要开发者按[手工包格式](CUSTOM_PETS.md)放置。当前在线适配假定 8 列 x 9 行，不保证所有 Petdex 图集版本、动作和布局可用。

下载包保存来源信息，但不等于完成授权核查。保留作者和许可证，分别确认修改、使用、展示和再分发权限；不能把第三方角色一概标为 MIT，也不能以“非商业”替代授权。

## 存储与隐私边界

| 位置 | 保存或读取内容 |
| --- | --- |
| `%USERPROFILE%\.codex` | 读取 `sessions` 中的 JSONL、状态数据库和错误日志数据库，不是本工具的卸载目录 |
| `%LOCALAPPDATA%\CodexTaskMonitor\settings.json` | 提醒、桌宠、启动和 API 等设置 |
| `%LOCALAPPDATA%\CodexTaskMonitor\monitor.db` | 任务快照、读取位置、提醒去重记录；可能包含标题、项目、路径、活动和错误信息 |
| `%LOCALAPPDATA%\CodexTaskMonitor\logs` | 本工具诊断日志；分享前检查敏感信息 |
| `%LOCALAPPDATA%\CodexTaskMonitor\integration.json` 和 `state.json` | API 启用时的连接信息/令牌和状态快照；关闭 API 不等于清除已有状态文件 |
| `<project-root>\Pets\<id>` 或 `<app-folder>\Pets\<id>` | 从程序目录向上遇到最近的 `.sln` 时用该目录的 `Pets`，否则放程序旁；不是按终端当前目录选择 |

即使程序解压到其他盘，用户数据和 .NET 临时解压缓存仍可能使用系统盘。不能承诺不使用 C 盘。

当前代码未发现向远端上传任务内容的路径，但监控会解析会话，标题可能取自用户消息片段。Petdex 目录、缩略图和下载会连接第三方服务器及目录引用的资源主机；通常会暴露 IP、请求目标等网络信息。浏览器访问还遵循浏览器及网站自身的隐私行为。这不是“完全不联网”的工具。

隐私模式默认开启，但不是全局匿名开关：

| 表面 | 当前遮盖范围与残留 |
| --- | --- |
| 提醒 | 替换标题和活动；单条提醒仍可能显示项目名 |
| HTTP / WebSocket API | 替换标题和活动；项目名、线程/父线程标识、深链、时间及部分代理信息仍可返回 |
| `state.json` | 替换标题和活动，清空工作目录与会话文件路径；保留项目名、标识等其他字段 |
| 数据库、诊断、主窗口、悬浮列表、截图 | 不会因此匿名化，不应直接公开 |

更改隐私模式后请退出并重新打开监视器，使 API 和状态文件按新的启动设置工作。它不会追溯清理旧数据库、日志、文件副本或截图。本仓库公开测试截图统一使用合成任务、占位路径和原创内置“薄荷终端”（`mint`），不使用个人下载桌宠、真实聊天或私人目录。

## 本机 API

“启用桌宠 API”默认开启，端口默认 `47831`，只监听 `127.0.0.1`。启用/关闭或更改端口后，需要退出并重新启动监视器。端口必须为 1024 至 65535 之间未被占用的值。

| 接口 | 用途 | 认证 |
| --- | --- | --- |
| `GET /api/v1/health` | 服务健康、暂停状态和任务数量 | 无 token |
| `GET /api/v1/tasks` | 当前任务快照 | `Authorization: Bearer <token>` |
| `GET /api/v1/tasks/<thread-id>` | 单个任务 | 同上 |
| `WS /api/v1/events` | 初始快照和后续事件 | 握手时同上 |

地址、WebSocket 地址和每次 API 启动生成的 token 在 `%LOCALAPPDATA%\CodexTaskMonitor\integration.json`。不要分享这个文件，不要把端口转发到公网。回环监听和 token 不等于能防住拥有本机文件访问权限的程序；不需要集成时可关闭 API 后重启。该 API 没有执行 Codex 任务的接口。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 看不到某个任务 | 清空搜索和项目筛选，检查三个分组、暂停状态、默认 Codex 数据位置；点刷新/监控状态。发现范围和格式兼容有限，不要删 Codex 数据来重置 |
| 状态与 Codex 不一致 | 以 Codex 为准；恢复监听或重启监视器，提供脱敏的事件格式与复现步骤 |
| 没有完成弹窗 | 检查勿扰、普通完成选项，以及监视器主窗口是否在前台；旧记录、子任务、合并更新不一定单独提醒 |
| 点任务未定位聊天 | 在 Codex 内手动查找，确认应用安装与协议关联；不要把启动成功等同于聊天定位成功 |
| Petdex 加载或下载失败 | 重试/取消，检查网络和服务可用性，先用内置角色；不要运行来源不明的安装命令 |
| 自制桌宠不出现或动作错位 | 检查专用元数据、文件名、图集和动作顺序，参见自制桌宠说明 |
| 连接本机 API 失败 | 检查已启用并重启、端口冲突和本次 token；API 失败不一定代表任务监控已停止 |

## 更新与卸载

更新前先从托盘退出。将新包解压到单独目录，核对版本后再替换程序；若搬动程序，检查 `Pets` 的实际位置和自动启动设置。桌宠可能留在旧的程序目录或源码项目目录，设置和数据库则仍在本工具的 LocalAppData 目录。

卸载时先关闭自动启动并保存，再从托盘退出，删除自己解压的应用目录。需要清除本工具记录时，可在退出后另行删除 `%LOCALAPPDATA%\CodexTaskMonitor`；先确认是否要保留设置、记录或自制宠物，并单独处理遗留的 `Pets`。不要删除共享源码目录中的其他文件。

**不要删除 `%USERPROFILE%\.codex`、Codex 聊天、工作项目或其他个人 Codex 文件夹来卸载本工具。** 本工具的状态记录和 Codex 自己的会话不是同一份数据。
